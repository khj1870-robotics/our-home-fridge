독립 실행 버전(저장을 IndexedDB로 교체)을 만들면서 이 폴더로 옮깁니다. 지금 쓰는 본 앱은 Claude 아티팩트에서 동작합니다.

## 12월 6일 제출까지의 완료 기준

목표는 핵심 흐름이 제대로 동작하는 것입니다. 세부 기능과 화면 품질은 과제 제출 뒤로 미룹니다. 시간이 부족하면 아래 '필수 기능'만 남기고 나머지 탭은 숨깁니다.

**필수 기능 (한 기기 시연)**: 예시 영수증 입력 → 냉장고 재고 → 식단에 재료 넣기 → 먹음 처리 → 새로고침 후에도 유지

| 작업 기간 | 일정표 작업 | 확인할 결과 |
| --- | --- | --- |
| 11-24 | 범위 확정·저장소 만들기 | 필수 기능과 숨길 기능 승인. 독립판은 테스트 사본 코드를 그대로 쓴다. |
| 11-24 ~ 11-27 | 독립 실행 버전 | 11/24~25 로그인 없이 열고 새로고침 후에도 재료가 남는다. 11/26~27 예시 영수증→식단→먹음→남은 재고까지 연결. |
| 11-28 ~ 11-29 | 돈 계산 개편 6단계 | 핵심 검산 4가지만: 먼저 산 재고 차감, 할인 배분, 사용액+잔액=구입액, 먹음 중복 차감 없음. |
| 11-29 ~ 12-02 | 테스트·버그 수정 | 11/29 첫 사용자가 설명 없이 저녁 한 끼 기록. 11/30~12/1 Android·iPhone 확인. 12/2 수정과 재검사. |
| 12-03 | README 작성 | 실행법, 스크린샷, 데모 GIF, 출처 대조. |
| 12-04 ~ 12-05 | 실행 확인·제출 | 12/4 다른 환경에서 ZIP 리허설. 12/5 저장소 URL과 ZIP 제출. 12/6은 예비일. |

**과제 제출 뒤로 미룬 일**: 버린 돈 기록·검산식 표시(7단계), 본 앱 데이터 이전, 두 계정 공유, UI·UX 전후 측정과 개선 항목, 글자 확대·자정/월말 같은 세부 점검, 중복 영수증 등록 방지, 새 디자인.

첫 시연에서는 [예시 영수증](../data/sample/README.md)을 입력하고 임박한 재료를 골라 두 사람의 저녁을 기록합니다. 재고, 식비, 남은 재료를 확인한 다음 같은 끼니를 다시 열어봅니다. 시험 기기, 실제 결과, 막힌 단계는 개발 기록에 남깁니다. 과제 마감은 12월 6일 23:59이며 ZIP과 저장소 URL은 같은 버전을 가리켜야 합니다.
